# 冻结 v0.2 后的有界 PPO 续训

目标是改善完整对局名次。腾位启发式未达到开发门槛后，改用现有终局名次目标继续更新网络，
不将循环次数、动作一致率或训练时名次当作晋级依据。

## 已冻结的设置

协议和原始材料位于 `runs/ppo-continue-20261028/`。

- 起点：冻结 v0.2 部署权重；三个新训练种子 90000000、91000000、92000000，共享同一起点。
- 每种子固定 50 更新、204800 决策；首个种子包含已完成的 3 更新兼容探针，再恢复 47 更新。
- 32 环境、rollout 128、minibatch 128、2 epochs、CPU 单线程、MPS 更新；一次只运行一个训练器。
- 原有终局目标 `1-2*(placement-1)/7`，决策成本 0.0003，参考 v0.2 的 KL 正则系数 0.03，学习率 3e-5。
- 混合脚本/冻结启发式训练对手，打乱准备轮次调度；没有训练用的真实对局校准对手库。
- 每次调用最多 600 秒、3 GiB 进程 RSS 或 MPS 驱动分配上限。检查发生在原生调用之间。
- 默认遇到截断停止，保留错误；中断后核实实际检查点再决定续跑，不挑更早检查点代替固定第 50 更新。
- 部署时统一 RepeatGuard limit=1、move budget=0，不叠加腾位、移位退出或取消记忆。

与历史训练相比，这次新建优化器，参考 KL 策略改为 v0.2 起点，学习率也降低；
只能评价“这套续训方案相对不续训”的结果，不能把收益单独归因于某一超参数。
三个种子是共享父模型的训练随机性复核，不是三次从零复现。

## 开发与独立验收

开发偏移 81000，三种候选加 v0.2，每种策略在脚本、启发式、混合学习对手中各 128 局，共 1536 局。
完整八席轮换，对手包括未用于此次训练的冻结 BC→PPO 模型。
评测使用同一只读审计入口，逐行 `policy` 标签统一为 `baseline`（表示未叠加实验规则的加载模式）；
真实策略身份由目录角色、checkpoint SHA256 和 manifest 区分，不能按这个通用标签混合权重。

三个固定检查点全部评测后，候选须平均名次至少改善 0.05，任何场景平均退步不超过 0.15。
符合者中选择等权平均名次最好的一个；并列选训练种子最小者。报告三个结果，不在本轮调参或扫检查点。

通过后冻结唯一候选，才使用 final 偏移 140000，每策略每场景 512 局，共 3072 局。
平均名次至少改善 0.10，配对 95% 区间上界小于 0，各场景区间上界小于 +0.15；全部完成、零非法动作。
重采样单位是完整八席种子块，三个场景同种子一起抽取，10000 次，统计 RNG 20261031。
开发区间不校正选模偏差；最终区间只评价被选定的冻结候选。

## 操作和续跑

首个种子的恢复命令（输出目录必须尚未创建）：

```bash
.venv/bin/python -m omnibob.train \
  --resume runs/ppo-continue-20261028/probe/latest.pt \
  --updates 47 --device mps --max-seconds 600 --max-rss-gib 3 \
  --output runs/ppo-continue-20261028/seed90000000
```

其余种子使用 `--initialize` 加载冻结 v0.2，并使用各自 `config-<seed>.json`，固定 50 更新。
完整命令记录在本轮 `training-runner.jsonl`，评测命令在 `development-runner.jsonl`。
每个训练调用仍保留自身 manifest、metrics、summary、原子 checkpoint 和定期检查点。

恢复前核实 journal 中的 PID 与实际命令是否匹配。不要重新运行已完成的整组 runner。
训练中断时，读取 summary 和安全 checkpoint 的 update 数，补足到 50，使用新的输出目录并记录父链。
失败检查点不能恢复，须诊断后从更早安全边界恢复；保留失败运行。
评测的每局记录原子写入，原进程退出后可用原命令加 `--resume` 续跑未尝试局，不能删除失败局重抽。

全部开发结束后：

```bash
.venv/bin/python -m omnibob.continuation_report runs/ppo-continue-20261028 --stage dev
```

统计通过仅代表可以继续工程验收，不等于已发布或已获线上比赛授权。
冻结 v0.2 和原 practice 不变，不读凭据、不参赛、不推送；额度耗尽时保存状态，绝不使用重置。

## 开发结果与候选冻结

三个种子各完成 50 更新，合计 614400 决策，无截断、无丢弃；所有 1536 局开发对照正常完成、零非法动作。

| 训练种子 | 脚本名次差 | 启发式差 | 混合学习差 | 等权平均差 | 开发门槛 |
|---|---:|---:|---:|---:|---|
| 90000000 | +0.2891 | -0.3438 | -0.5078 | -0.1875 | 未通过 |
| 91000000 | +0.0156 | -0.1406 | -0.3984 | -0.1745 | 通过 |
| 92000000 | +0.1953 | +0.0469 | -0.0859 | +0.0521 | 未通过 |

负值有利于候选。选择种子 91000000 的固定第 50 更新；其开发等权配对 95% 区间 [-0.348958, +0.015625]，尚不是独立强度证明。
第一种子虽然平均改善更多，但脚本场景退步超过预设限制，不能取代通过门槛的候选。

选中候选的开发改善/退步最大案例分别从 8→1 和 1→8，完整重跑均复现。
首次分歧前可见输入一致，后续随机轨迹随策略分叉；不能把最终结果简单归因于某一步。
这些诊断没有用于修改候选。完整记录位于 `candidate91000000-diagnostics.json`。

`CANDIDATE_FREEZE.json` 保存权重、控制器、协议、开发判定和报告程序摘要。
final140000 在冻结前未发现已有运行；接下来执行预设 3072 局独立验收，默认版本仍为 v0.2。

## 独立验收：不晋级

3072 局全部正常完成、零非法动作；每格 512 局，平均名次越小越好。

| 对手 | 冻结 v0.2 | 候选 91000000 | 名次差 |

| scripted | 2.1055 | 1.9941 | -0.1113 |
| heuristic | 2.4941 | 2.4922 | -0.0020 |

等权平均名次差 -0.041016，完整八席种子块配对 95% 区间 [-0.166016, +0.080745]。
未达到改善 0.10 和区间上界小于 0 的预设标准；启发式与混合学习场景的非劣性区间限制也未通过。
**不晋级，冻结 v0.2 继续作为默认基线。** 开发改善没有在新验收种子上得到清晰复现。
这不是证明续训绝无收益，也不能改用吃鸡率、动作减少或测试通过替代名次门槛。

没有根据验收结果选择另一训练种子；另外两条分支不能用同一 final140000 再参加选模。
final140000 已使用。失败结果、逐局数据、训练父链与冻结候选均保留，没有发布新默认版本。

## 下一项优先验证

本轮三种子续训并未消除这个已知实现差别。先量化部署时被控制器改写的动作比例，再决定是否做训练/部署 mask 对齐的单变量实验。
