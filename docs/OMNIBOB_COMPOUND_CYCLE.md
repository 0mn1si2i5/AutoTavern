# 打出—取消—移位：本地单变量实验

2026-10-28，接续[首场 practice 复盘](OMNIBOB_PRACTICE_REVIEW.md)。本轮不读取账号凭据、
不连接竞技队列、不再参赛、不启动训练。冻结 v0.2 权重和上一轮连续移位控制器保持原样。

## 问题与修复边界

旧反例：开发种子 `1000021006`、席位 5、脚本对手、打乱轮次调度。
上一轮候选完成 525 次决策，64 次立即打出/取消，第 12、13 回合触及操作上限。
64 次取消中，62 次返回观测只改变操作计数；另两次还发生了公开对手信息变化。
旧 RepeatGuard 将棋盘排列纳入状态键，移位后同一张牌能重新进入打出/取消回路。

`omnibob/cancel_memory.py` 新增独立 `CancelMemoryPolicy`：

1. 记录实际返回的 Play，以及紧接着实际返回的 Cancel；不根据模型未执行的提案记历史。
2. 等待下一份玩家可见观测，确认取消确实回到打出前的状态。只忽略己方操作计数和棋盘排列顺序。
3. 在此状态下暂时屏蔽同一手牌格的 Play 编码；保留 Cancel、选目标、移动和所有其他合法动作。
4. 任何其他可见变化形成新的状态键，可以重新考虑施法；换回合清空历史。

键保留金币、手牌、商店、技能、统计量和公开对手信息；棋盘按包含身材和附加物的实体排序，
不同身材的同名卡不会混为一张。操作合法性始终以原生 mask 为限，没有合法备选时保留原 mask。
控制器只调用下层策略一次，放在完整旧控制器外层，避免为丢弃的动作提案更新内部历史。

组合为 `CancelMemory(RepeatGuard(ReorderExit(LearnedPolicy)))`。单变量对照是它与
`RepeatGuard(ReorderExit(LearnedPolicy))` 的比较；冻结 v0.2 同时作为最终强度基准。
没有修改旧 RepeatGuard、ReorderExit、模型文件、默认部署加载器或原生引擎。

这是启发式约束，不是策略等价证明：移位可能让相邻目标法术变得更有价值，因此屏蔽重试也可能伤害名次。
仅覆盖立即 Play→Cancel 且已确认状态复原的手牌回路；不覆盖先多次选项再取消、技能取消或所有可逆操作。
公开对手信息更新会允许重试，这一保守选择也意味着不能声称循环已完全消失。

旧反例重跑：新增规则将触及额度回合从 2 个降为 0 个、决策从 525 降为 493、取消从 64 降为 53、
名次从 3 变为 2。它只用于确认局部修复，不属于新种子验证，也不能替代完整统计。

## 预先固定的实验

`runs/compound-cycle-20261028/PROTOCOL.json` 和 `POLICY_FREEZE.json` 在正式开发评测前写入。
已有运行 manifest 中未发现选定偏移冲突，记录于 `seed-audit.json`。

| 项目 | 设置 |
| --- | --- |
| 权重 | `runs/releases/omnibob-v0.2-20261028/policy/policy.pt`，SHA256 `3e0efb0636a2d7abd2b51c1dfea1757e254193630d0e4309cd3942ab6b26f787` |
| 三个策略 | `baseline` 冻结 v0.2；`cycle_exit` 上轮候选；`compound` 只增加取消记忆 |
| 对手 | 七个脚本机器人；七个冻结启发式机器人，分别评测 |
| 开发 | dev 偏移 41000，每策略每场景 256 局，共 1,536 局 |
| 验收 | final 偏移 110000，每策略每场景 512 局，共 3,072 局 |
| 配对 | 完整八席轮换；相同初始种子、配置、对手、打乱轮次调度；策略分叉后不保证相同商店 |
| 资源 | 每次最多两个 CPU worker，每个模型一个推理线程，每场景最多 1,800 秒 |

验收时查询本机系统可用内存比例为 28%，两个独立场景并行运行，每场景仍为两个 worker，
合计最多四个评测 worker；资源快照留档。测得的延迟是实际并行运行延迟，不是隔离硬件基准。

一个固定候选，不根据开发名次继续调参。开发晋级条件为：全部正常完成且无非法动作，
新增规则相对 `cycle_exit` 在**每一场景**的平均名次退步均不超过 0.15。未通过则保留验收种子未使用。

最终强度晋级必须同时满足：

- 对两个对手场景等权汇总，相对 **v0.2 和 cycle_exit 两个对照**的配对名次差 95% 区间上界都小于 0。
- 每个场景相对 v0.2 的区间上界均小于 +0.15，避免平均收益掩盖某一场景退步。
- 所有验收局正常完成、零非法动作。

名次越小越好。减少操作、取消或额度触发都只作诊断，不能代替名次晋级。
两个场景使用相同种子，汇总时先对同种子的两个场景等权，再对完整八席种子块 bootstrap，
不能把场景或席位当作独立样本。最终决策使用 10,000 次重采样、统计 RNG 20261029；
单场景评测脚本原有的 5,000 次区间仅为附加输出。每场景验收只有 64 个环境种子块。

时间上限在原生调用之间检查；失败与中断保留，不能静默重试后只保留成功结果。

候选只通过上述实验 CLI 或 `load_compound_policy` 显式加载。冻结 v0.2 默认入口不变，

## 开发结果

每格 256 局，平均名次越小越好：

| 对手 | 冻结 v0.2 | 上轮 cycle_exit | 新 compound | 新增规则的名次差 |
| --- | ---: | ---: | ---: | ---: |
| 脚本 | 1.9609 | 1.9609 | 1.9648 | +0.0039 |
| 启发式 | 2.5508 | 2.7773 | 2.7812 | +0.0039 |

1,536 局全部完成、零非法动作。两场景的新增规则名次差均小于预设 +0.15，因此按原计划进入验收，
未根据开发结果修改候选。启发式场景中新候选相对 v0.2 退步 +0.2305，开发区间 [0.0156, 0.4492]；
主要差异已存在于上轮 cycle_exit，不能归因于这次取消记忆。

开发集上，新规则将脚本对手的取消总次数从 115 降为 87，启发式从 193 降为 150；
各场景触及额度的对局均从上轮候选的 1/256 降为 0/256。这些效率数据不作为晋级依据。

退步案例也已保留：脚本种子 1000041014、席位 0，名次退步 1；启发式种子 1000041008、席位 5，
名次退步 3。各自重新跑完整对局复现结果，第一次动作分歧处的可见输入完全一致，新增规则将原本
的再次施法改为激活随从。两条轨迹随后分叉，不能把最终名次损失归因为单步激活本身。
证据在 `dev-regression-diagnostics.json`，没有因此重新调参或删除坏结果。

## 独立验收结果与晋级决定

每行 512 局，两个场景合计 3,072 局：

| 对手 / 策略 | 平均名次 | 吃鸡率 | 前四率 | 取消总次数 | 触及额度的对局 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 脚本 / 冻结 v0.2 | 2.1680 | 37.9% | 92.8% | 294 | 263/512 |
| 脚本 / 上轮候选 | 2.0723 | 43.9% | 93.8% | 327 | 2/512 |
| 脚本 / 新增取消记忆 | 2.0742 | 43.8% | 93.6% | 236 | 0/512 |
| 启发式 / 冻结 v0.2 | 2.5215 | 42.6% | 83.0% | 440 | 257/512 |
| 启发式 / 上轮候选 | 2.4219 | 45.7% | 85.2% | 507 | 3/512 |
| 启发式 / 新增取消记忆 | 2.4199 | 46.3% | 85.2% | 375 | 0/512 |

相对两个对照的等权汇总配对名次差，负值有利于新增规则：

| 对照 | 平均名次差 | 95% 区间 | 强度晋级条件 |
| --- | ---: | --- | --- |
| 冻结 v0.2 | -0.09766 | [-0.21484, +0.02346] | 未通过：上界不小于 0 |
| 上轮候选：隔离新增规则 | +0.00000 | [-0.00488, +0.00488] | 未通过：上界不小于 0 |

**决定：不晋级，冻结 v0.2 继续作为默认基线。**
相对 v0.2，两场景分别通过预设 +0.15 的非劣性阈值，但没有达到要求的强度优越性标准。
相对上一轮候选，新增规则的平均名次增益恰好为 0；1,024 个配对局中 6 局更好、5 局更差、1,013 局名次相同。
这不是声称在所有环境中绝无作用，而是在本次两种冻结对手分布上没有可确认的强度增益。

操作效率的改善单列：相对上一轮候选，触及额度对局从 5/1,024 降至 0/1,024，
取消次数从 834 降至 611（减少 26.74%）。零次触及额度仅是本批样本的结果，不保证任意对局无循环。
取消本身仍可能合理，不能把剩余 611 次一概标为错误，也不能把被屏蔽次数当作节省动作数。

新增规则每次都会计算观测键；实际平均决策延迟：脚本场景从上轮候选 1.789 ms 到 1.885 ms，
启发式场景从 1.801 ms 到 1.908 ms。这是并行运行观测值，效率改进没有免除额外计算成本。

- 原反例、开发退步案例、最初未实现模块时的失败测试输出也保留；没有删除阴性结果。
- 未修改引擎或训练权重，未提交或推送代码，未参赛。所有实验进程结束。

## 对后续研发的含义

当前本地分布上，继续处理这类低频复合循环主要改善运行质量，尚不足以推动名次。
下一项更值得验证的是经营决策：持有战吼牌何时打出、替换哪个随从、何时把金币用于升本或即时战力。
先建立这类真实可见局面的诊断与完整对局对照，再决定新的有界学习实验；本轮没有擅自展开新训练。
