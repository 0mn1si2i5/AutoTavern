# OmniBob v0.2 复现范围与主动简化

本实现以 `fb61201a557ddd36a411cf44aac51ce4d9b606ce` 为基点，在 Mac 本机编译。
采用 rizling.top 公开 observe2 补丁后，TavernGym 为1.1.0，原游戏规则逻辑保持不变。
它是独立实现的实验 Agent，不是作者发布的 TavernAgent，也没有作者权重。

## 与论文方法的差别

论文第6节、附录C描述实体Transformer、PPO和经过真实对局校准的对手库。
论文网络18M参数、宽384、8层/8头；附录F报告8张H200与128CPU核资源。
附录D使用模型建议、人工执行。上述是论文报告，不是本机实验成绩。
[论文 v1](https://arxiv.org/html/2610.33845v1)

本机18GB统一内存，先测量后选择32并行环境、128步rollout、128minibatch。
observe2暂不由原生BatchEnv提供，因此使用独立VectorGames；原生CPU模拟与Python学习吞吐分开报告。
模型不使用文本embedding、论文规模网络、真实比赛校准、论文完整课程或辅助名次预测目标。
等权重融合仅是额外的单网络后处理实验，并非论文复现要求。

默认终局效用是自定的 `1 - 2*(placement-1)/7`，gamma=1。
部分实验每个决策另扣0.0003，使用GAE lambda=0.995、参考初始策略KL系数0.03。
参考KL与每次PPO更新的target-KL提前停止不同。这些配置必须随结果保存；不能将引擎默认奖励
或这些自定选择称作论文最终目标。简单自我对弈也不等于论文的完整训练方法。

遇到引擎回合/战斗截断，默认停止；明确允许截断的实验保留错误和计数，丢弃该轨迹当前rollout片段，
不使用强制名次奖励。此前已通过价值估计更新的片段无法追溯撤销。评测排除截断局，配对比较只使用
双方都正常完成的完整八席种子块，另列实际完成局数和被排除数量。

## 可重复性的边界

每次实验保存Git基点、各源码文件SHA256、环境/观测/动作/卡表合同、规则、训练参数、
随机种子、运行控制器及逐局结果。后续实验还保存可恢复的源码覆盖包；早期模仿与热身阶段
仅有源码摘要，没有当时全部源码的完整归档，不能承诺逐字节重建早期训练过程。保留的初始化
权重及其摘要允许从冻结阶段继续复现实验。训练种子在`[0,10^9)`，开发在`[10^9,2*10^9)`，
最终验收在`[2*10^9,3*10^9)`。最终选模前冻结权重和协议，验收后不据结果修改模型。
公开TavernBench不作为独立选模证据。最终验收种子使用后也不再是未来版本的未见测试集。

CPU检查点边界恢复经过逐参数、环境和RNG一致性测试；MPS已恢复并继续完成实际更新，
但不承诺跨PyTorch、macOS或GPU版本逐位一致。部署包去除优化器、环境存档和随机状态，
可推理或初始化训练，不能精确续训。原始训练检查点和全部失败日志保留在本机`runs/`。

公开竞技战绩没有中间观测、动作、种子、手牌和商店，不能重建校准轨迹。
仍需用户授权的真实比赛/人工游戏记录，才能开始分析模拟到实战的差距。

`scripted`是按原样保留的上游参考比较器，具有原生chooser回调。其部分选项使用游戏RNG，
Python绑定在选择后恢复该RNG，因此不能把它称作独立外部随机策略。OmniBob自己的随机、
启发式和学习策略没有Game/RNG句柄；此差异已在v0.1接口说明中区分，v0.2继续保留。
没有让模型利用已知未来随机流进行搜索；上游参考对手与真实异步参赛者仍有分布差异。
