## 假设与边界

前一轮训练掩码对齐实验完成5376局，六个候选全部未过开发门槛，且纯启发式对手组均退步。
这使“当前训练对手混合不能提供足够适应不同对手的学习信号”成为下一项可检验假设；还不是已证实的根因。

本轮将训练对手从 `mixed`（原生脚本、冻结启发式）改为 `mixed_learned`（脚本、启发式、冻结 v0.2）。
模型结构、初始化、学习率、终局效用与决策成本、参考 KL、更新预算、调度和控制器均保持一致。
学习者使用原生合法掩码，部署都使用原 RepeatGuard=1。对手权重不随学习者更新，所有模型只读取各自玩家可见信息。
这仍是合成对手库，不是论文的真实比赛校准库，也不是完整自我对弈方法复现。
冻结 heldout-bc300 继续只用于评测，不能进入训练对手。

## 配对与资源

- 训练种子96000000、97000000、98000000，全部从原冻结 v0.2 开始；每个新候选固定50更新、204800决策。
- 复用上一轮预先固定的全部三个原生掩码控制模型，不挑选其中成绩差的子集，也不重复训练。
- 96000000 两侧均为3更新后精确续跑47更新，另两组均一次50更新。保存全部来源和中断记录，不挑中途模型。
- 原有控制只用于比较，不能换一批开发种子后重新报名晋级；只有本轮三个新候选有选模资格。
- 复用控制不是同时重训，训练耗时差不能解释为因果性能开销；MPS也不承诺跨运行逐位复现。
- 一个MPS训练进程，每调用最多1800秒、3GiB；最多两个CPU评测进程。额外资源费用为零。

此前独立资源探针（训练种子105000000，不参与本轮选模）完成12288决策，用时79.25秒、峰值RSS约0.50GiB，
MPS驱动分配约1.11GiB，无截断或丢弃。它仅确定本机可行性。

## 命令

已有后台任务不要重复启动。先检查control.json、runner journal、实际PID和结果。训练例子必须使用新输出目录：

```sh
.venv/bin/python -m omnibob.train \
  --initialize runs/releases/omnibob-v0.2-20261028/policy/policy.pt \
  --config runs/frozen-opponent-20261028/config-97000000.json \
  --rules configs/arena-v2.json --updates 50 --device mps \
  --max-seconds 1800 --max-rss-gib 3 --output runs/my-new-opponent-training

# 完整阶段结束后生成报告；已有报告拒绝覆盖
.venv/bin/python -m omnibob.opponent_report runs/frozen-opponent-20261028 --stage dev
.venv/bin/python -m omnibob.opponent_report runs/frozen-opponent-20261028 --stage final
```

报告核对真实部署权重、原始控制散列、训练来源、匹配配置、工具链、完整种子/座位、规则、对手与运行时。
记录失败并保留原始数据，不补跑替换失败来制造通过。通过名次门槛后仍须核验候选接口、发行材料及回退路径，才改变本地默认。
