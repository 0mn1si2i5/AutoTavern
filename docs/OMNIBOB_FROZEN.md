# OmniBob 项目冻结说明

2026-11-17 起暂停开发和训练。这份说明记录停在哪里、为什么停、文件放在哪里、以后恢复时先做什么。

## 一、冻结时的状态

- 分支 `omnibob-v0.2-local`，标签 `omnibob-frozen-20261117`。
- 本地默认模型是 v0.3（2026-11-01）。v0.3 对 v0.2 的 21,888 局配对评测中，平均名次好 0.099（95% 区间 0.064 到 0.134）。评测对手是模拟器里的脚本和启发式 bot。
- v0.4 候选（2026-11-02）相对 v0.3 平均名次好 0.042，没有注册为发行。
- Windows 长训练（`configs/long-stage-v03.json`，19,000 次更新）的配置、脚本、说明和功耗调节窗口已经做完，并在 Windows 上用同一份配置试跑过低功耗、暂停、停止和续跑。正式训练没有启动。
- 实机入口是只读建议面板。实机自动对局试过一次，基本不能正常操作，自动操作入口已移除。
- 没有天梯分数。模型和训练对手都没有在天梯上测过。

## 二、暂停的原因

训练数据全部由模拟器生成。下面四项都没有和真实对局核对过，所以不能确认继续训练会提高实机水平。

1. 规则版本。本地引擎是 36.6.3，线上是 37.0.2。上游提交 `1c2086a`（2026-11-04）实现了 37.0.2，没有合入。
2. 模拟结果。战斗和商店的模拟结果没有和真实对局系统地比对过。
3. 模型输入。模型的 52 个输入块里，没有一块在实机日志上完全核实：12 块能直接取得但不完整，其余要靠累积事件推算或者取不到。逐块清单是实验记录包里的 `runs/offline-replay-20261107T021819Z/review/OBSERVE2_FIELDS.csv`。
4. 对手。训练对手是固定的脚本和启发式 bot。

另外查过公开资料，没有找到可以批量获取的高分玩家对局回放。

## 四、恢复时的顺序

1. 新开分支，把引擎升到 37.0.2，用实机日志核对卡牌数值。引擎一升级，v0.3 和更早的检查点会因为环境指纹不符而拒绝加载，现在没有迁移工具，所以不要直接在 `omnibob-v0.2-local` 上升级。
2. 用真实对局日志比对模拟的战斗结果和商店变化。
3. 逐块核实模型输入，核实不了的先屏蔽。
4. 换对手。上游论文的做法是用高分玩家的统计和真实阵容建对手库，每回合抽阵容，再按实机遇到的对手强度校准。
5. 前四步做完再长训练。[Windows 训练说明](OMNIBOB_WINDOWS_TRAINING.md) 里的配置和脚本可以直接用，训练目录要重新初始化。

真人对局数据的来源：自己的 `Power.log`；观战高分好友时自己客户端的日志（没有验证过）；请高分玩家提供日志或 HDT、Firestone 的回放；HSReplay 按分段的聚合统计。个人能收集到的量大概是几十到几百局，够做第 2、4 步和评估，不够单靠模仿训练。

参考：上游论文 [Build, Don't Play](https://arxiv.org/html/2610.33845)，[第三方评审](https://rsi.watch/claims/autotavern/)，[HSReplay XML 格式](https://github.com/HearthSim/hsreplay-xml)。
